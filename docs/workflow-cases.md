# 工作流排错案例

以下案例由源记录中的工作流问题脱敏整理，保留原编号便于追溯。它们是方法说明，原私人会话和证据文件未公开；新部署环境需要自行复验，不能直接沿用源环境的“已验证”状态。

## CORR-20261020-003：从摘要回执取 session_id 报错

派发摘要提供 `job_file`，持久字段 `session_id` 保存在该路径对应的 `job.json`。集成程序若直接从摘要读取，会触发 `KeyError`。应先按回执读取任务文件，再查询原会话。当前派发回归测试覆盖回执与任务状态。

## CORR-20261020-004：只读沙箱的 here-doc 无法创建临时文件

有的 shell 会为 here-doc 创建临时文件，在只读沙箱内可能报 `cannot create temp file`。短检查可使用 `python3 -c` 或读取已存在的脚本；确需写文件时按原任务权限处理，不自动扩大沙箱。

## CORR-20261024-009：iCloud 占位文件导致读取等待

macOS 文件可能带 `dataless` 属性，读取或复制时等待。先检查具体文件属性，再按权限规则逐文件运行 `brctl download`。原命令返回了运行会话时，恢复文件可读后继续等待同一进程，避免重复启动任务。导出到本地目录后可按 SHA-256 核对副本一致性。

## CORR-20261026-001：Luna app-server 退出

派发进程退出不能说明任务已经完成。保留失败回执，确认原执行不再运行，核对已有产物后再决定接回剩余工作。需要业务判断或新权限时由协调者处理，不能悄悄切换模型并声称原任务成功。

## CORR-20261102-001：等待 DSH 时跳过结果或重复执行

必须等待当前轮结束、返回内容并读取 `result.txt`，才能整合、验收或推进依赖任务。等待期间只做独立工作；运行较久和暂时没有输出不构成接管理由。`submission_unknown` 先查询同一会话，`needs_attention` 先处理请求并核实状态。

## CORR-20261102-002：技能校验器缺少 PyYAML

`quick_validate.py` 依赖 PyYAML。缺少依赖时保留原错误，使用已存在且获准使用的依赖环境重跑。窄范围静态检查只能说明实际检查的字段和结构，不能冒充原校验器通过。核心安装器和离线派发测试不依赖 PyYAML。
